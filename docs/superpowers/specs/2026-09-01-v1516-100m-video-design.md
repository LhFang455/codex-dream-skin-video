# Codex Dream Skin v1.5.16 与 100 MiB 视频主题设计

## 背景

当前个人修改版基于上游 `Fei-Away/Codex-Dream-Skin` v1.5.14，并增加了 macOS 本地视频主题。上游已经发布 v1.5.16，其中包含 Codex 26.818 界面兼容、输入框识别、可见性校验和热重载等修复。当前应用的更新检查仍指向上游仓库，因此直接安装提示中的上游 DMG 会覆盖个人修改版的视频引擎。

现有视频实现还有两项已知限制：

1. 导入、写入、切换和注入器分别硬编码了 20 MiB 上限；
2. 大于 10 MiB 的视频使用临时回环 HTTP 地址，但热切换会结束旧注入器并创建新的端口和令牌，同时在视频真正加载前报告成功，可能留下灰色背景。完整重启后能播放，说明视频文件和渲染能力本身并非主要故障点。

## 目标

- 以官方上游 v1.5.16 标签对应的发布提交为新基线。
- 保留当前图片主题、Odette Pro 视频主题、菜单栏切换、暂停、恢复和启动能力。
- macOS 本地 MP4/WebM 视频主题上限提高到 100 MiB。
- 不转码、不重新压缩视频，保留源文件字节和画质。
- 所有视频通过本机回环流媒体服务播放，避免把视频 Base64 数据放入 CDP 注入载荷。
- 主题热切换只有在视频真实可播放且主题版本匹配后才报告成功。
- 更新检查指向 `2698685648/codex-dream-skin-video`，避免引导用户安装会移除视频功能的上游包。
- 在替换 `/Applications/Codex Dream Skin.app` 前完成源码测试、独立 App 构建和 80 MiB 实际视频验证，并在需要退出 Codex/ChatGPT 时暂停等待用户操作。

## 非目标

- 不支持在线视频地址、网络视频下载或远程媒体服务器。
- 不内置 FFmpeg，也不自动转码或改变分辨率、码率、帧率。
- 不承诺所有 MP4/WebM 编码组合都能被 Chromium 解码；大小合格但编码不兼容时必须明确失败。
- 不为 Windows 添加视频导入界面。本次只保证共享运行时生成和既有 Windows 图片功能不回归。
- 不修改普通图片主题的视觉设计或现有主题数据格式。

## 升级策略

以 v1.5.16 发布标签的提交作为明确边界，将其合并进当前视频分支，保留上游历史和本仓库的三个视频/说明/CI 提交。冲突只在双方共同修改的运行时、注入器、菜单栏公共脚本和测试中处理。

冲突解决遵循以下优先级：

1. 选择器、Codex 26.818 兼容、可见性校验、菜单栏和安全校验采用 v1.5.16；
2. 视频媒体类型、视频渲染节点、视频专用透明样式和视频主题入口保留个人修改版行为；
3. 视频逻辑写入 `runtime/` 规范源，再由 `tools/sync-runtime-assets.mjs` 生成平台资产，禁止只改编译后的 `macos/assets`；
4. 版本号使用 `1.5.16`，应用名称和安装路径保持 `Codex Dream Skin.app` 不变。

## 视频数据流

### 导入与保存

1. 菜单栏或脚本选择本地 MP4/WebM。
2. 在复制前检查它是普通文件、非空且不超过 100 MiB。
3. 原样复制到活动主题目录和主题库，不执行转码。
4. 继续使用 `theme.json` 作为提交标记：媒体文件先落盘，配置最后发布，避免观察到半成品主题。
5. 切换已保存视频主题时使用同一 100 MiB 上限；图片主题保持原有限制。

### 运行时播放

1. 持久注入器启动一次仅监听 `127.0.0.1` 的 HTTP 服务，操作系统分配端口，并生成高熵随机路径令牌。
2. 视频响应支持字节范围请求；增加 `Cache-Control: no-store`，不允许代理缓存。
3. 视频地址包含媒体内容指纹，例如 `...?v=<fingerprint>`。主题切换后即使服务端口和令牌不变，浏览器也会请求新媒体。
4. 注入载荷只携带这个短地址、媒体类型、主题元数据和 CSS，不携带视频内容。
5. 渲染器创建静音、循环、自动播放、`playsInline` 的固定全屏 `<video>`，图片主题继续使用现有 Blob URL 路径。

服务仅接受令牌路径上的 `GET`/Range 请求，不暴露目录列表，不接受客户端提供的文件路径，也不监听局域网地址。当前文件路径只保存在注入器进程内存中。

## 热切换协议

热切换不再终止一个健康的持久注入器。

1. 切换脚本发布新主题并写入“正在应用”操作状态。
2. 现有 watcher 检测 `theme.json` 和媒体变化，验证新主题，更新服务器当前媒体指针并生成带新指纹的载荷。
3. watcher 注册新的早期注入脚本；视频主题执行一次 `Page.reload(ignoreCache: true)`，让媒体地址在文档初始化阶段安装。
4. watcher 等待渲染器验证：主题 ID 和 revision 匹配、视频节点存在、`readyState >= 2`、宽高大于零、未处于错误状态，并且播放时间在短间隔内推进。
5. 只有全部通过才写入成功状态。切换脚本等到这个成功结果后再向菜单栏返回成功。
6. watcher 缺失时先启动 watcher，再执行同样验证；验证超时或播放失败时报告具体失败原因，并进入现有完整重启兜底。兜底仍失败时不得显示成功。

静态图片主题继续走 v1.5.16 的正常热应用路径，不强制页面重载。

## 大小、内存与格式边界

视频最大值定义为一个共享的 100 MiB 常量，导入、写入、切换和注入器测试必须引用相同语义，避免再次漂移。运行时永不 Base64 编码视频，因此 CDP 载荷大小与视频大小无关。

主题导入/切换阶段允许为稳定性校验临时读取最多 100 MiB 文件；播放阶段使用文件流和 Range 请求，不把整段视频常驻到渲染器内存。100 MiB 是本次明确的产品边界，不扩展为“无限大小”。

支持范围仍为 Chromium 可解码的 MP4/WebM。文件扩展名和大小检查通过不等于编码兼容；真实播放验证是最终判定标准。

## 更新来源与版本提示

个人修改版的更新脚本改为查询 `2698685648/codex-dream-skin-video` Releases。README 继续明确说明本项目基于上游、遵守原许可证并仅作个人非营利修改。上游的新版本需要先经过合并和视频回归，再发布到个人仓库；应用不会直接提示下载上游 DMG。

## 错误处理

- 超过 100 MiB：复制前拒绝，并显示实际大小和允许上限。
- 文件在校验或复制期间变化：沿用稳定文件/快照检查并拒绝。
- 回环服务器不能启动：主题保存可保留，但应用失败，不进行虚假成功确认。
- Range 非法：返回 HTTP 416；媒体消失或已被替换：返回 404。
- 浏览器解码失败、尺寸为零或播放时间不推进：报告视频不可播放，尝试一次完整重启兜底。
- 热切换验证失败：保留可诊断日志和操作失败状态，菜单栏不显示成功。
- 更新合并导致图片主题回归：停止安装阶段，保留当前已安装 v1.5.14 App。

## 测试与验收

### 自动测试

- 100 MiB 边界：空文件和超过上限拒绝，边界内接受。
- 任意大小视频载荷中不出现 `data:video/...;base64`，载荷尺寸保持有界。
- 回环服务只绑定 `127.0.0.1`，令牌错误返回 404，Range 返回正确的 206/416。
- 更换媒体后 URL 指纹变化、旧内容不被缓存。
- 健康 watcher 的视频热切换不会终止 watcher 或更换服务器。
- watcher 在视频切换时执行一次 reload，并在播放验证通过后完成操作。
- 播放验证失败不会写入成功状态，完整重启兜底路径仍存在。
- `runtime/` 与 macOS/Windows 生成资产完全同步。
- v1.5.16 上游新增回归、现有视频回归、macOS/Windows 可移植测试和载荷完整性检查全部通过。

### 实际验收

使用现有约 80 MiB Odette 源视频建立测试主题：

1. 独立测试 App 可以导入且不压缩文件；保存后的媒体 SHA-256 与原文件相同。
2. 冷启动播放正常，视频尺寸正确，循环、静音和全屏裁切正常。
3. 从图片主题切换到 80 MiB 视频、视频切换到图片、再切回视频，均不出现持续灰屏。
4. 菜单栏只在可播放验证通过后显示成功。
5. 新建对话、已有对话、设置/插件等非背景页面保持既定范围，图片主题视觉无回归。
6. 当前 Odette Pro 主题仍存在且可选择。

## 发布与回退

1. 不直接修改当前 `/Applications/Codex Dream Skin.app`。
2. 构建独立测试 App 和 DMG，完成自动测试及 80 MiB 实际验收。
3. 保存当前 App 和活动主题的可恢复副本。
4. 在需要退出 Codex/ChatGPT 前停止，等待用户确认已经关闭。
5. 使用相同应用名称和路径替换正式 App，再做一次冷启动和菜单栏切换验收。
6. 验收失败时恢复原 App 和主题副本；源码变更仍保留在 Git 分支以便诊断。
7. 最终通过后提交、推送个人仓库并由 Actions 构建个人修改版 Release。
